## 1. Rules
1. Components first: anything on two or more frames (variants, sheets and backdrops included) is an instance of a local main component. No detached instances, no look-alike frames, no "Card / ..." rebuilt by hand. A screen = Status bar + `Ohm / Header` + instances + `Ohm / Footer` or Bottom nav + home indicator. If the same group of instances repeats on 3 or more frames, wrap it in a component.
2. Properties, not sublayer edits: use text, boolean, instance-swap and variant properties. A Button, Badge or Row nested in a bigger component is marked exposed (`isExposedInstance = true`) and set from outside with `outer.exposedInstances[i].setProperties(...)`. A missing option is added to the main component as a variant or property; never make a near-duplicate and never change how an existing variant looks.
3. Text styles: every text node uses a library text style (keys in round 1 BUILD_GUIDE). The rupee sign is its own styled text inside `Ohm / Amount`. No em or en dashes.
4. Variables: every fill and stroke is bound to a `brand` variable (including `line-strong`) or library `card` for white, with the real hex as base colour (gotcha 3). No new variables. Icons are lucide instances (check old kit names, e.g. alert-circle for circle-alert); after any icon swap re-apply the stroke to the slot's token. Shadows only via `Shadow / Toast`.
5. Where: Foundations page, one Section per builder (table below), names `Ohm / <Name>`, variant values in Title Case. Log a row in "Built" (section 6) before anyone uses the component. An area component needed by a second area is moved to Base by the lead, never copied.

### Order, places, decisions
- Order: BASE A and BASE B in parallel (B never nests A) > HOME, SUMMARY, CHECKS, TRENDS, READING in parallel > SHARE > CONNECTION > FOUNDATIONS. Start only when every Base row you need is in Built. Cross-area dependency: CHECKS (S07 hero) and SHARE (S11) consume READING's `Illustration / Bill`; wait for its Built row.
- Sections on Foundations, all at y 6000, each at most 2200 wide (Base 3400), grow height only, sets stacked in one column with 80 gaps: `Components · Base A` x 0 · `Components · Base B` x 3600 · `Components · HOME` x 7200 · `· SUMMARY` x 9600 · `· CHECKS` x 12000 · `· TRENDS` x 14400 · `Components · S04` (READING) x 16800 · `Components · SHARE` x 19200 · `Components · CONNECTION` x 21600.
- Card container decision: `Ohm / Card` is a component with a SLOT. Every card component (Price ladder, Problem card, ...) has an `Ohm / Card` instance as its root and fills the slot in its main. Fallback if slot creation fails twice: a documented card recipe frame as root (fill `card`, radius 16, no stroke, clip on, vertical auto layout, padding 20); say so in Built.
- Changes vs BUILD_GUIDE_R2: `Ohm / Trust line, Razorpay` is built by BASE A (Footer nests it); SUMMARY must not build it. `Bill status mini` Size and Tile are added by BASE B (its Reassurance row needs them), not SUMMARY. Outline buttons become Secondary, Ghost buttons become Link. S12 has no 3xl heading: `Ohm / Header` Top level, title "Trends". Neutral data marks are `line-strong` everywhere, S08 share bars and kVA bars included. Copy link shows `Ohm / Toast` "Link copied". Past bills rows become 68 tall (List row), 8 shorter than round 1; frames hug.
